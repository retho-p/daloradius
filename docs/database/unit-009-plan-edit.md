# UNIT-009 — billing plan editing and profile replacement

`bill-plans-edit.php` keeps its existing PEAR display/existence queries but routes the dependent **write** sequence through `dalo_edit_billing_plan()` on one PDO handle and transaction. The helper locks the selected plan, validates and locks selected group names using the same three group sources as UNIT-008, updates the fixed allowlisted plan columns using bound values, removes old mappings, and inserts all replacements with bound values. Any failure rolls back the header, old associations, and new associations. It rejects malformed/nested input and does not expose PDO errors or bound SQL values. The shared profile validation from UNIT-008 is reused; the unconverted shared PEAR mapping helper remains in place for other callers.

The edit form now submits a distinct `planActive` control rather than another `planRecurring` control. GET/POST no longer strips `%` from an existing plan name; this intentionally repairs edits of plans with percent signs, which UNIT-008 can create. A missing/invalid plan cannot be edited.

Validation: `PYTHONDONTWRITEBYTECODE=1 python3 tests/plan_edit_http.py` exercises disposable PHP HTTP/MariaDB 11.8 containers and synthetic operator sessions. Compare the first success path's normalized plan fields and associations with the PEAR snapshot using `PLAN_EDIT_ROOT=<PEAR snapshot>` to capture JSON and `PLAN_EDIT_BASELINE_JSON=<captured JSON>` on the candidate. Candidate-only checks include authentication, ACL, CSRF, malformed POST fields, nonexistent profiles and plans, an empty mapping selection, quotes and percent signs, a named database location, and a unique-index collision on the **second** new association proving rollback after the header update, deletion, and first replacement insertion. Also run `tests/plan_create_http.py` as a regression for the shared validator. No live database or application stack is touched, and the existing InnoDB schema needs no migration SQL.

Limits: this unit does not migrate the read/display path or the other billing plan pages. No foreign keys protect mappings against independent legacy writers, and no schema-level unique plan-name constraint prevents all concurrent duplicates. The shared table identifier quoting is MySQL-style: this flow was exercised on MariaDB, not PostgreSQL, and unsupported PDO engines fail closed without PEAR write fallback.
